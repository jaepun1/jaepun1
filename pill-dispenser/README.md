# เครื่องจ่ายยา 7 ชั้น × 6 ช่อง: เฟิร์มแวร์และการเชื่อมต่อเว็บแอป

```
เว็บแอป ──WebSocket ws://<IP>:81──▶ ESP32-S3 CAM ──UART──▶ บอร์ดหลัก ESP32
   ▲                                  │ ถ่ายภาพ                 │ หมุนถาด / ดันยา / เพลง / เซนเซอร์ / จอ
   └──────────── สถานะ, ภาพ, รับยาแล้ว ◀┴─────────────────────────┘
```

| โฟลเดอร์ | คืออะไร |
|---|---|
| `main_board/` | เฟิร์มแวร์บอร์ดหลัก + `diagram.json` + `libraries.txt` สำหรับ Wokwi |
| `esp32s3_cam/` | เฟิร์มแวร์ ESP32-S3 CAM (Wi-Fi, WebSocket, กล้อง, ส่งต่อคำสั่ง) |
| `webapp/` | เว็บแอปที่แก้แล้ว (ภาพ 2 ภาพ, เลขชั้นคงที่) |
| `simulator/` | เครื่องจำลองบน Node.js สำหรับทดสอบเว็บแอปโดยไม่ต้องมีฮาร์ดแวร์ |
| `original/` | สำเนาโค้ดและวงจรเดิมจาก Wokwi (โปรเจกต์ Jaiya) |

## การทำงาน

1. ในเว็บแอปเลือกวันและเวลา แล้วกด **บันทึกและส่งไปที่เครื่อง** เว็บจะส่ง `time` (ตั้งนาฬิกา) และ `schedule` ไปให้เครื่อง บอร์ดหลักจะเก็บไว้ในหน่วยความจำถาวร ไฟดับแล้วตารางไม่หาย
2. **ถึงเวลา** บอร์ดหลักจะหมุนถาดไปยังช่องนั้น เลื่อนตัวดันไปยังชั้นนั้น แล้วดันยาออก ระหว่างนี้เว็บจะเห็นสถานะ `moving` → `ready` → `dispensing` และโมเดล 3D ขยับตาม
3. **เซนเซอร์ตรวจยา** ตรวจพบว่ายาลงถาด กล้องจะถ่าย**ภาพที่ 1** (`phase: "dispensed"`)
4. **เปิดเพลง**มาริโอ้ (โค้ดเพลงเดิม) หยุดได้ด้วยปุ่มจอยสติก ปุ่มน้ำเงิน หรือเมื่อหยิบยาออก
5. **ถ้ายายังค้างในถาด** เครื่องจะเปิดเพลงซ้ำทุก 5 นาที รวมสูงสุด 3 รอบ
6. **เมื่อหยิบยาแล้ว** (ถาดว่างต่อเนื่อง 1.5 วินาที) เครื่องจะส่ง `taken` ไปที่เว็บ ช่องนั้นจะเปลี่ยนเป็น "รับยาแล้ว" และกล้องจะถ่าย**ภาพที่ 2** (`phase: "taken"`)
7. ถ้าเกิน 1 ชั่วโมงแล้วยังไม่หยิบ เครื่องจะบันทึกว่า "ไม่ได้รับยา" (ตรงกับที่เว็บแสดง)

**จอ OLED** แสดงเวลา วัน/วันที่ มื้อถัดไป (เวลา, ชั้น, ช่อง) IP ของเครื่อง (มีคำว่า `WEB` เมื่อเว็บเชื่อมอยู่) และแถบ `PILL READY` เมื่อมียาค้างในถาด

## การต่อวงจร

### บอร์ดหลัก (ESP32 DevKit)

| อุปกรณ์ | ขา ESP32 | หมายเหตุ |
|---|---|---|
| OLED SSD1306 + RTC | SDA 21, SCL 22 | เดิม |
| จอยสติก VRX / VRY / SW | 34 / 35 / 25 | เดิม |
| บัซเซอร์ (ผ่าน R 220Ω) | 26 | เดิม |
| **UART ไปกล้อง** RX2 / TX2 | **16 / 17** | ต่อไขว้กับกล้อง และต่อ GND ร่วมกัน |
| เซอร์โวหมุนถาด | 18 | servo1 เดิม (เดิมยังไม่ได้ต่อขาสัญญาณ) |
| เซอร์โวแขนดันยา | 19 | servo2 ใหม่ |
| L298N IN1 / IN2 / ENA (มอเตอร์เลื่อนตัวดัน) | 32 / 33 / 23 | ใน Wokwi แสดงด้วย LED เขียว/แดงชุดกลาง (led3/led4) |
| **เซนเซอร์ตรวจยา EC-BOT PU** Out / Vcc / Gnd | **36 (VP)** / **3V3** / GND | สัญญาณ analog · ใน Wokwi ใช้ตัวต้านทานปรับค่า (potentiometer) แทน: หมุนไปทางซ้าย = มียาในถาด |
| LED เขียว (เว็บเชื่อมต่อ) | 13 | led1 เดิม |
| LED แดง (มียาค้างในถาด) | 14 | led2 เดิม |
| ปุ่มเขียว: ทดสอบจ่ายมื้อถัดไปทันที | 4 | btn1 เดิม |
| ปุ่มน้ำเงิน: หยุดเพลง | 5 | btn2 เดิม |

### ESP32-S3 CAM ↔ บอร์ดหลัก

| ESP32-S3 CAM | บอร์ดหลัก |
|---|---|
| GPIO 21 (TX) | GPIO 16 (RX2) |
| GPIO 14 (RX) | GPIO 17 (TX2) |
| GND | GND |

บอร์ดกล้องที่ใช้คือ **ESP32-S3 N16R8 CAM + OV2640** (ผังขาแบบเดียวกับ Freenove ESP32-S3 CAM) ขากล้องในโค้ดตั้งไว้ตรงกับบอร์ดนี้แล้ว GPIO 14 และ 21 ว่าง ไม่ชนกับกล้อง ห้ามใช้ GPIO 35–37 (PSRAM) และ 43–44 (USB-UART) ต่ออุปกรณ์อื่น

> ⚠️ **เซนเซอร์ตรวจยา**: ต่อขา Vcc เข้า **3V3** ห้ามต่อ 5V เพราะขา Out จะส่งแรงดันได้สูงถึง 5V ซึ่งเกินที่ขา ESP32 รับได้ (3.3V)
> ⚠️ **ไฟเลี้ยง**: เซอร์โว มอเตอร์ และกล้องกินกระแสสูง ควรใช้แหล่งจ่าย 5V แยก (เช่น 18650 + บอร์ดเพิ่มแรงดัน) และต่อ GND ร่วมกับ ESP32

## ติดตั้ง

### บอร์ดหลัก
- Arduino IDE → Board: **ESP32 Dev Module**
- ไลบรารี: RTClib, Adafruit GFX Library, Adafruit SSD1306, **ESP32Servo**, **ArduinoJson (v7)**
- ถ้าเครื่องจริงใช้ **DS3231** (ตามรายการอุปกรณ์ในเว็บ) ให้เปลี่ยน `RTC_DS1307 rtc;` เป็น `RTC_DS3231 rtc;` และเปลี่ยน `if (!rtc.isrunning())` เป็น `if (rtc.lostPower())`
- ค่าที่ต้องปรับให้ตรงกับเครื่องจริงอยู่ส่วน "ค่าที่ปรับได้" ด้านบนของไฟล์ ได้แก่ `TRAY_ANGLE` (มุมของแต่ละช่อง), `PUSH_OUT`, `LIFT_MS_PER_FLOOR` (เวลาที่ใช้เลื่อน 1 ชั้น) และ `IR_THRESHOLD` / `IR_PILL_WHEN_LOW` (ดูหัวข้อเซนเซอร์ตรวจยาด้านล่าง)

### ESP32-S3 CAM
- Board: **ESP32S3 Dev Module**, Flash Size: **16MB**, PSRAM: **OPI PSRAM**, Partition: **16M Flash (3MB APP/9.9MB FATFS)**
- เสียบสาย USB ช่องที่เขียนว่า **COM** (หรือ UART) และตั้ง USB CDC On Boot: **Disabled** ถ้าเสียบช่อง **USB** (OTG) ให้ตั้งเป็น **Enabled** แทน ไม่อย่างนั้น Serial Monitor จะไม่ขึ้นข้อความ
- ถ้าอัปโหลดไม่ขึ้น ให้กดปุ่ม BOOT ค้างไว้ แล้วกด RST 1 ครั้ง จากนั้นค่อยปล่อย BOOT
- ไลบรารี: **WebSockets** (Markus Sattler), **ArduinoJson (v7)**
- แก้ `WIFI_SSID` / `WIFI_PASS` ถ้าต่อ Wi-Fi ไม่ได้ กล้องจะเปิดฮอตสปอต `PillDispenser` (รหัส `12345678`) ให้แทน ที่อยู่คือ `ws://192.168.4.1:81`
- เปิด Serial Monitor ดู IP หรือดูจากจอ OLED ของบอร์ดหลัก

## เซนเซอร์ตรวจยา (EC-BOT PU)

เซนเซอร์ตัวนี้มี LED สีฟ้าส่องแสงลงไป และมี phototransistor วัดแสงที่สะท้อนกลับ ค่าที่อ่านได้จะต่ำเมื่อเจอสีขาว (สะท้อนแสงมาก) และสูงเมื่อเจอสีดำหรือไม่มีอะไรอยู่ใกล้ ๆ เซนเซอร์อ่านได้แค่ระยะใกล้มาก ประมาณ 2–10 มม.

**วิธีติดตั้งที่แนะนำ**
- เจาะรูที่พื้นถาดรับยา แล้วติดเซนเซอร์ไว้ใต้รู หันหน้าขึ้น
- ทำพื้นถาดให้ลาดเอียงลงหารู เพื่อให้เม็ดยาไหลไปทับรูเสมอ
- **ถาดว่าง** แสงส่องออกไปไม่มีอะไรสะท้อนกลับ จึงอ่านได้**ค่าสูง**
- **มียา** เม็ดยาบังรูและสะท้อนแสงกลับ จึงอ่านได้**ค่าต่ำ** (โค้ดตั้งไว้แบบนี้: `IR_PILL_WHEN_LOW = true`)
- ถ้าติดเซนเซอร์ด้านบนแล้วส่องลงไปที่พื้นถาด ให้ทาพื้นถาดเป็น**สีดำด้าน** เพื่อให้ตัดกับยาเม็ดสีขาว ถ้ายาเป็นสีเข้ม ให้ใช้พื้นถาดสีขาวและตั้ง `IR_PILL_WHEN_LOW = false`
- ใช้พลาสติกหรือฉากบังแสงรอบเซนเซอร์ เพราะแสงจากห้องจะทำให้ค่าเพี้ยน

**วิธีตั้งค่า (calibrate)**
1. อัปโหลดโค้ด แล้วเปิด Serial Monitor (115200) บอร์ดจะส่งค่า `"ir":` ออกมาทุก 2 วินาที หรือพิมพ์ `{"cmd":"ir"}` เพื่อดูค่าทันที
2. จดค่าตอน**ถาดว่าง** (เช่น 3500) และตอน**วางยา 1 เม็ด** (เช่น 600) ให้ลองกับยาทุกแบบที่จะใช้จริง
3. ตั้ง `IR_THRESHOLD` ให้อยู่กึ่งกลางระหว่างสองค่านั้น (เช่น (3500 + 600) / 2 ≈ 2000) แล้วอัปโหลดใหม่
4. ค่าบนกล่องสินค้า (ขาว < 100, ดำ > 800) วัดจากบอร์ด Arduino ที่อ่านได้ 0–1023 ส่วน ESP32 อ่านได้ 0–4095 ค่าที่เห็นจึงประมาณ 4 เท่า (ขาว < 400, ดำ > 3200)

## ทดสอบ

### 1. ใน Wokwi (บอร์ดหลักอย่างเดียว)
คัดลอก `main_board/main_board.ino`, `diagram.json` และ `libraries.txt` ไปวางในโปรเจกต์ Wokwi แล้วกดรัน Wokwi ไม่มีกล้อง ให้พิมพ์คำสั่งลงใน Serial Monitor แทน:

```
{"cmd":"time","y":2026,"mo":11,"d":11,"h":8,"mi":59,"s":50}
{"cmd":"schedule","data":{"floors":[{"floor":1,"date":"2026-11-11","slots":[{"slot":1,"on":true,"time":"09:00"}]}]}}
```
รอ 10 วินาที เครื่องจะหมุนและดันยา จากนั้นหมุน potentiometer ไปทางซ้ายสุด (ยาลงถาด) เพลงจะดังขึ้น แล้วหมุนกลับไปทางขวาสุด (หยิบยา) จะเห็นข้อความ `{"type":"taken",...}` ใน Serial Monitor ระหว่างนี้ข้อความ `{"type":"snap",...}` คือคำสั่งที่จะส่งให้กล้องถ่ายภาพ

คำสั่งอื่น: `{"cmd":"goto","floor":3,"slot":4}`, `{"cmd":"dispense","floor":2,"slot":1}`, `{"cmd":"stop"}`, `{"cmd":"ir"}` (ดูค่าเซนเซอร์)

### 2. ทดสอบเว็บแอปกับเครื่องจำลอง (ไม่ต้องมีฮาร์ดแวร์)
```
cd simulator
npm install
npm start
```
ในเว็บแอปไปที่แท็บ SETTING ใส่ `ws://localhost:81` แล้วกด "ทดสอบเชื่อมต่อ" จากนั้นลองกด "หมุนและดันยา" หรือตั้งเวลามื้อเป็นนาทีถัดไป เครื่องจำลองจะส่งสถานะ ภาพ 2 ภาพ และ "รับยาแล้ว" (หยิบอัตโนมัติหลัง 10 วินาที) กลับมาให้ ในเทอร์มินัลกด `t` = หยิบยา, `p` = วางยา

### 3. ทดสอบจากแท็บ SETTING ของเว็บ (กับเครื่องจริงหรือเครื่องจำลอง)
เชื่อมต่อเครื่องก่อน แล้วใช้ 3 ส่วนนี้:

- **ทดสอบการทำงาน**: เลือกชั้นและช่อง ใส่ยา 1 เม็ดในช่องนั้น แล้วกด **เริ่มทดสอบ** เครื่องจะทำทุกขั้นเหมือนมื้อจริง และเว็บจะติ๊กผลทีละขั้น ✓/✕ ได้แก่ หมุนถาด → ดันยา → เซนเซอร์เจอยา → ภาพที่ 1 → เพลง → หยิบยา → ภาพที่ 2 ถ้าขั้นไหนไม่ผ่าน จะบอกสาเหตุไว้ใต้ขั้นนั้น (เช่น ค่าเซนเซอร์ที่อ่านได้) การทดสอบ**ไม่บันทึกลงตารางยา** และภาพทดสอบไม่ไปปนกับภาพของมื้อจริง ถ้าไม่หยิบยาภายใน 2 นาที ขั้น "หยิบยา" จะถือว่าไม่ผ่าน กด **ยกเลิก** เพื่อหยุดกลางทางได้ ใต้รายการยังแสดงค่าเซนเซอร์ตรวจยาแบบสด ใช้ช่วยตั้ง `IR_THRESHOLD`
- **ทดสอบกล้อง**: กด **ถ่ายภาพทดสอบ** กล้องจะถ่าย 1 ภาพมาแสดง ใช้ตรวจว่ากล้องทำงานและมุมกล้องเห็นถาดรับยา ถ้ากล้องเสียจะแสดงสาเหตุ
- **ช่องพิมพ์คำสั่ง** (ในส่วน "ทดสอบมอเตอร์และคำสั่ง"):

| คำสั่ง | ทำอะไร |
|---|---|
| `test 3 4` | ทดสอบครบวงจรที่ชั้น 3 ช่อง 4 (เหมือนปุ่มเริ่มทดสอบ) |
| `goto 3 4` | หมุนไปชั้น 3 ช่อง 4 |
| `dispense 3 4` | หมุนและดันยา |
| `photo` | ถ่ายภาพทดสอบ |
| `ir` | ดูค่าเซนเซอร์ตรวจยา |
| `stop` / `cancel` | หยุดเพลง / ยกเลิกการทดสอบ |
| `time` / `sync` | ตั้งเวลาเครื่องตามเว็บ / ส่งตารางเวลาใหม่ |
| `help` | แสดงคำสั่งทั้งหมด |
| `{...}` | ส่งคำสั่ง JSON ตรง ๆ |

กดลูกศรขึ้น/ลงเพื่อเรียกคำสั่งที่เคยพิมพ์ ผลลัพธ์แสดงในกล่องบันทึกด้านล่าง

เครื่องจำลองทดสอบกรณีผิดพลาดได้ด้วย: `NO_PILL=1 npm start` (เซนเซอร์ไม่เจอยา), `CAM_FAIL=1 npm start` (กล้องเสีย)

## เว็บแอป (`webapp/index.html`)

สำเนาของเว็บแอปเวอร์ชันล่าสุด (ฉบับเดียวกับที่ลิงก์ claude.ai) แก้ไขแล้ว 2 เรื่อง:

- **แสดงภาพ 2 ภาพต่อช่อง**: ภาพ "ตอนจ่ายยา" กับ "หลังรับยา" แสดงคู่กัน พร้อมเวลาที่ถ่าย (ภาพที่ถ่ายจากปุ่ม "ถ่ายภาพจากกล้อง" แสดงเป็นภาพที่ 3)
- **เลขชั้นของแต่ละวันคงที่**: เมื่อเลือกวัน เว็บจะกำหนดชั้นว่างให้วันนั้นและแจ้งว่าต้องใส่ยาชั้นไหน เลขชั้นนี้ไม่เปลี่ยนแม้ผ่านไปหลายวัน พอวันนั้นผ่านไปแล้ว ชั้นนั้นจะว่างให้ใช้กับวันใหม่ (ข้อมูลที่บันทึกไว้ก่อนแก้ จะใช้ลำดับวันที่เดิมเพื่อให้ตรงกับยาที่ใส่ไว้แล้ว)

**ข้อจำกัด**: หน้าเว็บที่เปิดจากลิงก์ https จะเชื่อมกับเครื่อง (`ws://`) ไม่ได้ เพราะเบราว์เซอร์บล็อก ให้เปิดเว็บจากคอมที่ต่อ Wi-Fi เดียวกับเครื่องแทน:

```
cd webapp
python -m http.server 8000
```
แล้วเปิด `http://localhost:8000` (จากมือถือในวง Wi-Fi เดียวกันใช้ `http://<IP ของคอม>:8000`) วิธีนี้โมเดล 3D ของเครื่องจริงจะแสดงด้วย ถ้าดับเบิลคลิกเปิดไฟล์ `index.html` ตรง ๆ ก็เชื่อมเครื่องได้ แต่โมเดล 3D จะเป็นแบบจำลองแทน

| ตั้งเวลา | `{"cmd":"time","y":2026,"mo":11,"d":11,"h":8,"mi":0,"s":0}` |
| ตารางเวลา | `{"cmd":"schedule","data":{"floors":[{"floor":1,"date":"2026-11-11","slots":[{"slot":1,"on":true,"time":"07:00"}]}]}}` |
| หมุนไปช่อง | `{"cmd":"goto","floor":3,"slot":4}` |

**เครื่อง → เว็บ**

| ข้อความ | ตัวอย่าง |
|---|---|
| สถานะทุก 2 วินาที | `{"type":"status","rtc":"08:00:05","floor":3,"slot":4,"pill":false}` |
| การเคลื่อนที่ | `{"floor":3,"slot":4,"state":"moving"}` / `"ready"` / `"dispensing"` |
| รับยาแล้ว | `{"type":"taken","floor":3,"slot":4,"at":"2026-11-11T08:03:10"}` |
| ภาพ | `{"type":"photo","floor":3,"slot":4,"phase":"dispensed","img":"data:image/jpeg;base64,..."}` |
| ผลทดสอบทีละขั้น | `{"type":"test","floor":3,"slot":4,"step":"pill","ok":true,"msg":"ค่าเซนเซอร์ 640"}` (step: `start` `move` `push` `pill` `ring` `taken` `done`) |
| ภาพทดสอบ | `{"type":"photo","phase":"test"}` (ปุ่มทดสอบกล้อง) หรือ `"test_dispensed"` / `"test_taken"` (ระหว่างทดสอบ) |
| กล้องถ่ายไม่สำเร็จ | `{"type":"photo_error","floor":3,"slot":4,"phase":"test","msg":"..."}` |
| บันทึก | `{"type":"log","msg":"..."}` |

**ภายในเครื่อง (UART)**: บอร์ดหลักส่ง `{"type":"snap","floor":3,"slot":4,"phase":"taken"}` ให้กล้องถ่ายภาพ ส่วนกล้องส่ง `{"type":"net","wifi":true,"ip":"192.168.1.50","clients":1}` ให้บอร์ดหลักทุก 3 วินาที
